# Rationale note

**How I selected data sources.** I needed a source that was free, covered regional as well as national press, and reached back nearly two years. The free plans of NewsAPI.org and GNews.io allow 100 requests a day and search only the last 30 days, so neither can build a history. Google News RSS needs no key, indexes the Indian English press widely and accepts date operators, so it became the backbone, queried one month at a time (1,196 queries, none hit the result cap). I added GDELT as an independent second index, Bing News RSS for recent weeks, and adapters for the keyed APIs as redundancy. Two of these did not deliver: GDELT rate-limited almost every call, and I had no keys for the others. The README says so. Article pages are read locally with trafilatura, so the pipeline costs nothing to rerun.

**Which states, and why.** I ran one identical query for all 28 states and ranked them by AI headlines naming the state. I took ten from the top with at least two per zone, so the result is not only the southern IT states. I added Andhra Pradesh, Madhya Pradesh and Rajasthan because my count had undersold the first two (headlines say "AP" and "MP") and so I could test the output against an independent list that covers them. Thirteen states, January 2025 to November 2026.

**Methodology.** Four query shapes per state per month, each aimed at one part of the brief's definition. Every response is cached, so the dataset rebuilds offline and identically. Relevance is decided by readable rules, and every item gets a reason code; the 8,322 rejected items are published so the line can be checked. The line: a state government, a body answering to it, or the state's High Court takes a concrete step involving AI. Opinion, speeches, central government actions, private-sector news and party politics are out. The state is read from the headline, never the query. Dates are converted to India time and carry a precision flag.

Deduplication took the most effort, because my first attempt was wrong in a way I could only see by measuring. I labelled 140 headline pairs by hand. Version one scored 0.98 precision but 0.58 recall: it split one announcement into many records. After fixing that, reading the clusters showed the opposite fault: a deal's signing and its cancellation had merged. I added two guards and re-measured: 0.89 precision and 1.00 recall on pairs held out from tuning.

I then read all 785 resulting headlines and removed 157 that were not state policy activity and 61 duplicates the method missed, leaving 567. The rules alone are right about four times in five, so I would not present their output unreviewed. Last, I scored the dataset against 85 events researched separately from official documents: it holds 56 percent of those in scope. The misses are tenders, gazette notices and budget lines that never become headlines. A news pipeline will not find those, and I would rather show that number than hide it.

**How I chose to present the data.** A reader asks "who is active" and "when", so the main view is a grid of states by months, shaded by number of records; selecting a cell lists them. Below it, a bar per state split by kind of step shows whether a state is writing policy, signing agreements or deploying systems, which one total would hide. A stage field (announced, signed, approved, launched) is there for the same reason: an announcement is not a working system. Every record links to its source and shows how many outlets reported it. The page is static and reads the file the pipeline writes, so page and CSV cannot disagree. A method section states what counts, shows the funnel from 9,473 items to 567 records, and lists the gaps.
